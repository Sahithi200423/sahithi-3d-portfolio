Native Language Learning & Acting Practice AI App

A specialized language learning and dramatic acting rehearsal platform (codebase: SceneLingo) engineered to help aspiring actors, creators, and bilingual learners master Indian languages—starting with Telugu—through English-letter transliteration, emotion studios, and rehearsal analytics.

Target Audience & Problem

The Aspiring Actor’s Bilingual Challenge

Aspiring cinema actors, voiceover artists, and theatre performers frequently face scripts in native Indian languages (such as Telugu) that they understand aurally but cannot read fluently in native script. Simultaneously, standard language apps teach robotic vocabulary without dramatic intention, vocal modulation, or emotional conviction.

SceneLingo bridges this gap by presenting scripts through English-letter transliteration and paired dramatic rehearsal studios—allowing performers to focus on emotional delivery, breath pauses, and cultural authenticity.

5-Tier Language Pedagogy

1. English Context:

Support prompt setting the conversational scene.

2. Native Script:

Authentic regional script (e.g. ఎలా ఉన్నారు?).

3. Romanized Transliteration:

Readable English lettering (e.g. "Ela unnaru?").

4. Phonetic Pronunciation:

Syllabic emphasis guide (e.g. "Eh-la un-naa-ru?").

5. Contextual Meaning:

Subtext & formality level (e.g. "How are you? (Polite)").

Implemented vs. Planned Features

Honest architectural audit based on source code and production audit records.

Fully Implemented in Source
  • ✓ Telugu Transliteration Learning: Full syllabus structured across English letters, native script, phonetics, and meanings.
  • ✓ Dialogue Lab (16 Scene Archetypes): Scripts spanning Romantic, Argument, Comedy, Audition, and Confrontation scenes with pause markers and intention tags.
  • ✓ "1 Line, 8 Emotions" Exercise: Dramatic flexibility tool allowing actors to practice a single line across multiple emotional deliveries.
  • ✓ Emotion Studio (20 Actor Emotions): Deep performance guides (Anger, Grief, Love, Vulnerability, Fear) covering internal thought, eyes, voice modulation, and 4 intensity levels.
  • ✓ Web Speech Synthesis: Client audio synthesis with locale matching (te-IN) and missing voice pack alerts.
  • ✓ Local Video Rehearsal Studio: Webcam recording via MediaRecorder API and video upload (MP4/WebM/MOV up to 100MB) stored safely in browser memory.
  • ✓ 8-Dimension Guided Self-Evaluation: Structured evaluation rubric for review without fabricating artificial AI scores.
  • ✓ Actor Mistake Bank (20 Categories): Structured 4-box mistake tracking (WHAT I DID, WHAT TO IMPROVE, WHY IT MATTERS, HOW TO FIX IT).
  • ✓ Dark / Light Mode Switcher: Fully responsive theme toggle with class-based Tailwind CSS tokens.
Planned / Unconnected Cloud Services
  • ⚡ Remote AI Video Analysis API:

    Service interface exists in videoAnalysisService.ts with hook VITE_VIDEO_ANALYSIS_API_URL. When unconfigured, the app transparently displays "Video analysis service not connected yet" and presents the self-evaluation rubric.

  • ⚡ Remote LLM AI Acting Coach:

    Abstracted in aiActingCoachService.ts with hook VITE_AI_COACH_API_URL. Currently operates cleanly in rule-based rehearsal demo mode.

  • ⚡ Automated ASR Speech Scoring:

    Automated acoustic phoneme pronunciation scoring is planned for future backend integration; speech is currently verified via client synthesis and actor self-review.

Engineering Methodology

AI-Assisted Workflow & Progressive Learning

An authentic reflection on utilizing AI pair programming to accelerate development while mastering complex browser APIs.

How I Built and Learned with AI

Throughout the development of SceneLingo, I used modern AI pair-programming tools as an intelligent engineering multiplier:

  • AI Assistance: Generating initial TypeScript boilerplate, structuring extensive linguistic transliteration datasets for Telugu, and designing comprehensive acting emotion matrices.
  • Progressive Learning: Building this project gave me hands-on mastery over browser media streams (getUserMedia), MediaRecorder memory lifecycles (revoking transient object URLs to prevent leaks), Web Speech API timeout watchdogs, and building resilient local-first applications.
  • Engineering Integrity: Rather than pretending remote computer-vision or AI speech models were functional, I intentionally architected the frontend with transparent fallbacks (rule-based coaching and guided self-reviews) when remote endpoints are unconfigured.
