CineBook: From Functional Prototype to Hardened Production Architecture

This case study breaks down the real architectural evolution between CineBook V1 (Initial Movie Ticket Booking Application) and CineBook V2 (Enhanced Movie Ticket Booking System). Every improvement, metric, and feature detailed here is verified against source code, git commits, and test outputs.

CineBook V1 — Initial Movie Ticket Booking Application

CineBook V1 served as the foundational proof of concept, focused on building the core booking workflow, dynamic seat map visual layout, and comprehensive internationalization.

Technology Stack

React 19 TypeScript Vite 8 Tailwind CSS 4 Node.js Express Supabase Postgres Prisma ORM

Verified Features

  • 128-seat auditorium map across VIP, Premium, and Standard rows.
  • 18-language interface with automatic Right-to-Left (RTL) mirroring for Urdu.
  • Multi-currency conversion supporting USD, INR, EUR, GBP, and JPY.
  • Initial 7-minute seat hold timer with client-side countdown.
  • Gatekeeper QR code ticket generation and scanner tab.

Prototype Boundaries

  • Seat holds were tracked in memory / application state.
  • Static movie card displays without 3D WebGL rendering.
  • Simulated checkout without cloud reverse-proxy rate limits.
  • Tested primarily with a 21-test pre-deployment regression script.
Phase 2 Architecture Commits: 3811c0e through 967894a

CineBook V2 — Enhanced Movie Ticket Booking System

CineBook V2 transformed the application into a hardened, high-concurrency platform with WebGL graphics, database-level locking, two-tier rate limiting, and 43 automated tests.

1. Three.js WebGL 3D Floating Ticket

Features a custom metallic cinema pass rendered dynamically in the hero section. Includes continuous 5-second sine wave vertical oscillation, strictly bounded tilt (10°–15° pitch/yaw), mobile touch event decoupling from page scroll, and an IntersectionObserver that pauses GPU rendering when offscreen.

Verified in Three.js Canvas Code

2. Atomic 10-Minute Concurrency Holds

Seat locks are acquired directly via PostgreSQL conditional INSERT ... ON CONFLICT DO UPDATE WHERE status != 'BOOKED' with a full 10-minute (600,000 ms) synchronized TTL. Competing attempts receive an immediate HTTP 409 Conflict. Enforces an 8-seat transaction ceiling.

Verified via Concurrency Tests

3. Cloud Security & Rate Limiting

Configured single-hop reverse proxy trust (trust proxy 1) for Render, mitigating X-Forwarded-For header spoofing. Deployed a two-tier rate limiter implementing per-account and per-IP hard caps guarding authentication, seat holds, and order creation.

Verified: 23 Security Tests Passing

4. Raw-Buffer HMAC Webhook Security

Integrated Razorpay Sandbox with server-side pricing enforcement (₹15 / 1500 paise per ticket). Webhook callbacks use raw request byte buffers (req.rawBody) for timing-safe HMAC-SHA256 verification and event idempotency to prevent duplicate bookings.

Verified in Webhook Handlers

Development Journey

Project Engineering Progression

How CineBook evolved incrementally through structured development phases.

Phase 1: Foundation (V1.0)

Proof-of-Concept Single Page Application

Constructed the core React 19 SPA, Tailwind CSS layout, dynamic 128-seat auditorium, 18-language internationalization (with Urdu RTL layout), and initial 7-minute seat hold timer.

Phase 2: Concurrency & State Refactoring

PostgreSQL Atomic Row Locking & State Resilience

Eliminated split-state race conditions and React error #310 during direct navigation. Migrated seat holds to PostgreSQL atomic conditional locks with a 10-minute synchronized TTL, returning HTTP 409 Conflict upon contention.

Phase 3: Visual Polish & 3D Engineering

Three.js WebGL Floating Cinema Pass

Integrated Three.js with bounded tilt physics (10°–15° pitch/yaw) and decoupled mobile touch gestures from native scroll. Implemented IntersectionObserver GPU throttling to save mobile battery.

Phase 4: Production Security Hardening

Cloud Edge Isolation & Webhook Idempotency

Configured single-hop proxy trust (trust proxy 1) for Render, two-tier IP hard caps, raw-buffer HMAC-SHA256 Razorpay webhook verification, and post-expiry payment reconciliation.

Phase 5: Automated Verification & Documentation

43/43 Passing Automated Regression Suites

Authored 23 security tests and 20 end-to-end booking verification tests covering multi-seat booking calculations, hold expiration, pricing integrity, and QR verification.

CineBook V3 — Luxury Black & Gold Interface, 3D WebGL & Performance Engineering

CineBook V3 represents the complete evolution into a showcase-grade full-stack cinema booking application. It introduces a bespoke champagne-gold cinema design, an interactive Three.js floating ticket hero, sub-second deep-link slug hydration, and parallelized database querying.

🌟 Luxury Design & 3D WebGL

  • Custom black-and-champagne-gold aesthetic with glassmorphic depth.
  • Three.js 3D ticket pass with bounded sine oscillation (10°–15° max tilt).
  • Touch-decoupled mobile interaction avoiding scroll interference.
  • IntersectionObserver automatically halts GPU render loops off-screen.

⚡ Verified Performance Breakthroughs

  • Sub-second deep-link render: Resolved compound slug matching (kalki → kalki-2898), cutting cold load from 4.6s to 919 ms (80% faster).
  • Parallelized Admin queries: Converted sequential database calls to Promise.allSettled, cutting resolution time by 55% (6.5s vs 14.4s).
  • Sub-second FCP: First Contentful Paint clocked at 796 ms (cold) and 452 ms (warm).

🔒 Portfolio Demo Mode & Safety

  • Uniform ₹5 demonstration ticket pricing across VIP, Prime, and Standard tiers.
  • Simulated e-commerce checkout with instant digital M-ticket generation.
  • Digital M-ticket pass rendered with visible demonstration watermark.
  • Zero real financial transactions or production database mutations.
